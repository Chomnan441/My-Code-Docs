# REST API

API ในเว็บแบบนี้คือช่องทางที่ Frontend ใช้ขอหรือส่งข้อมูลกับ Backend REST เป็นแนวทางหนึ่งในการออกแบบช่องทางนั้น โดยใช้เมธอดของ HTTP แยกประเภทงาน

ตัวอย่างด้านล่างเป็นตัวอย่างทั่วไป ไม่ใช่เส้นทางของ Job Application Tracker

## เมธอดที่ใช้บ่อย

| เมธอด | ใช้เมื่อ |
| --- | --- |
| `GET` | ขอข้อมูลมาแสดง |
| `POST` | ส่งข้อมูลใหม่ไปให้เซิร์ฟเวอร์บันทึก |
| `PUT` หรือ `PATCH` | ส่งข้อมูลไปแก้ไขของเดิม |
| `DELETE` | ขอบันทึกหนึ่งรายการให้ถูกลบ |

เซิร์ฟเวอร์ตอบกลับมาพร้อมรหัสสถานะ เช่น `200` คือสำเร็จ `201` คือสร้างข้อมูลแล้ว `404` คือไม่พบสิ่งที่ขอ และ `500` คือเซิร์ฟเวอร์ทำงานผิดพลาด

## ข้อมูลมักอยู่ในรูป JSON

JSON เป็นข้อความที่มีโครงสร้างแบบชื่อและค่า หน้าเว็บกับเซิร์ฟเวอร์ใช้ส่งให้กันได้

```json
{
  "title": "บริษัทตัวอย่าง",
  "status": "draft"
}
```

นี่ไม่ใช่รูปแบบข้อมูลของโปรเจค เป็นแค่ตัวอย่างว่า JSON หน้าตาเป็นอย่างไร

## อ่านโค้ด API อย่างไร

1. หาจุดที่ Frontend ส่งคำขอ แล้วดูเมธอดกับที่อยู่ที่เรียก
2. ไปที่ Backend แล้วหาฟังก์ชันที่รับที่อยู่นั้น
3. ดูว่าฟังก์ชันอ่าน JSON ที่ส่งมาหรือไม่ และตอบ JSON อะไรกลับ
4. ถ้ามีการแตะฐานข้อมูล ให้ตามต่อไปที่คำสั่ง SQL

เส้นทางจริงของโปรเจคจะถูกจดที่ [Backend](/projects/job-application-tracker/backend/) หลังจากอ่านซอร์สโค้ด
